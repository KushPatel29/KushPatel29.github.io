# kushpatel29.github.io

My portfolio site — live at **[kushpatel29.github.io](https://kushpatel29.github.io/)**.

Hand-built static page: one HTML file, one stylesheet, one script. No
framework, no build step, no tracker. The dashboard screenshots are real
captures from my repos, and every number on the page (test counts, model
results, NRV figures) is CI-verified in the repo it comes from — the same
rule the portfolio itself is built on: no claim without a number, and no
number without a test.

- `index.html` — all of the content, as real HTML. Nothing on this page is
  generated by JavaScript, so crawlers and link previews see the whole thing.
  Includes JSON-LD (Person + ProfilePage, and a CreativeWork per project).
- `styles.css` — dark + light themes. Authored in OKLCH, shipped as the exact
  sRGB conversions so it renders the same everywhere. Both themes are checked
  against WCAG AA.
- `main.js` — progressive enhancement only: theme toggle, scroll progress,
  work filter, count-up, scrollspy, lightbox, back-to-top. If it never loads,
  the page still reads correctly and every project is visible.
- `404.html` — branded not-found page, same palette and theme toggle.
- `robots.txt`, `sitemap.xml` — crawler basics.
- `assets/` — dashboard captures, OG banner, and `Kush-Patel-Resume.pdf`.
- `assets/fonts/` — Space Grotesk and JetBrains Mono, self-hosted (see below).
- `tools/` — the two CI checks described below.

## No third-party requests

The page makes **zero** requests off its own origin. The fonts used to come
from `fonts.googleapis.com`, which hands every visitor's IP to Google before
first paint — while the footer claimed "no tracker". Both families are
variable fonts, so one `woff2` each covers every weight the page uses: 53 KB
for the pair, vendored under SIL OFL 1.1 (`assets/fonts/LICENSE.txt`).

They're `<link rel="preload">`ed from the HTML because the `@font-face` rules
live in `styles.css`, which the browser can't discover until that sheet has
parsed.

## CI

`.github/workflows/verify.yml` runs two checks on every push and PR to `main`.

**`tools/check-links.mjs`** serves the repo the way GitHub Pages does,
HEAD-requests **every internal href and asset path** in `index.html` and
`404.html`, and fails the build on anything that isn't `200`. It also resolves
every in-page `#fragment` against the real element ids, so a renamed section
anchor can't quietly become a dead link, and asserts that all the "Download
Resume" CTAs point at exactly `assets/Kush-Patel-Resume.pdf`.

This exists because that file 404'd for a while and nothing caught it. A site
that argues claims should be verifiable shouldn't ship an unverified one.

**`tools/check-freshness.mjs`** fails the build if a content file changed but
the footer's "LAST UPDATED" date wasn't moved to match — a stale date is a
false claim like any other. Needs `fetch-depth: 0` to see real history.

Run either locally with `node tools/<name>.mjs` (Node 18+, no dependencies).

## Conventions worth keeping

- **Content lives in HTML, not JS.** The count-up animates *up to* a number
  that is already in the markup, and a watchdog restores the real value if the
  animation never runs — so it can never render a zero.
- **The terminal panel stays dark in both themes** — that's what the
  `--term-*` custom properties are for.
- **Filters are data-driven.** Each project carries `data-tags`; the chip
  count is derived, so adding a ninth repo needs no JS change. Filter state
  round-trips through `?filter=` so a subset can be linked to directly.
- **Cards are not one big `<a>`.** The thumbnail is its own button (it opens
  the lightbox) and the repo link is stretched back over the card body with
  `a.card-open::after`. Nesting them would be invalid HTML.
- **The compact nav menu hangs off the sticky header, not off its button.**
  The panel is wider than the button and the button isn't at the right edge,
  so anchoring to it pushes the panel off-screen on a phone.
- Grid tracks use `minmax(min(Npx, 100%), 1fr)` — the bare `minmax(Npx, 1fr)`
  form overflows narrow phones.

Checked at 360 / 390 / 768 / 1280 px: no horizontal page scroll, no nav
overlap, all tap targets ≥ 44 px, and zero contrast failures in either theme.
